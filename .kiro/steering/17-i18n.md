# Internationalization Rules (Part 31)
Launch languages: English, Spanish, Portuguese. Full product, not UI-only.

## Layers
| Layer | Rule |
|---|---|
| UI strings | Full catalogs EN/ES/PT via next-intl/ICU messages. Locale per user (profile) with tenant default. Pseudo-locale CI check for hardcoded strings. |
| Agent outputs | Every agent responds in the requesting user's locale. Documents draft in the tenant's document locale (Settings → Organization field). |
| ISO-KB | Retrieval filters `lang` first, falls back to EN with "translated from English source" marker. |
| Clause canon | Clause numbers and structure are language-invariant. The canonical spine stays single-source; only titles/text localize. |
| Legal stack | ToS/EULA/AUP/Privacy professionally translated. English version controls. Consent events record the language of accepted text. |
| Funnel & Snapshot | S0–S5 fully localized incl. pain-picker options. Pain quotes on the Spanish page must be Spanish-speaking pain, not translations. |
| Emails/PDFs | Localized templates; controlled-copy stamps localized. |

## Build rules
1. No hardcoded user-visible string anywhere in frontend/** or agent output.
   Every string goes through the i18n catalog.
2. Locale flows through the bedrock-invoker layer (one choke point, Part 22.3)
   — injected into every invocation context.
3. Nova family is multilingual across all three languages — no per-language
   model forks needed.
4. Clause-integrity hook validates against the canon regardless of display
   language (numbers are language-invariant).
5. Growth-content items carry a `lang` field; per-locale headline variants.

## Why
LATAM manufacturing is an underserved, consultant-dense ISO segment.
Trilingual launch targets the Americas + Iberia market.
